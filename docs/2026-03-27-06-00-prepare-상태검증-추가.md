# Prepare 단계 상태 검증 추가

## 프롬프트

```
Client error '400 BAD REQUEST' for url 'http://mirofish:5001/api/simulation/start'
```

## 원인 분석

`/api/simulation/start`에서 400 에러 발생. 페이로드 스키마 문제가 아닌 **시뮬레이션 상태 문제**.

### 근본 원인

MiroFish `SimulationManager.prepare_simulation()`이 엔티티 0건일 때 예외 없이 `state.status = FAILED`로 설정하고 정상 반환함.

```
prepare_simulation() returns state (status=FAILED)
  → run_prepare()에서 complete_task() 호출 (예외 없으므로)
  → 태스크 status = "completed"
  → 오케스트레이터 폴링이 "completed" 확인 → /start 진행
  → /start에서 state.status != READY 확인 → 400 반환
```

실패한 시뮬레이션: `sim_724e52698c69`
- `entities_count: 0`, `profiles_count: 0`, `config_generated: false`
- `error: "조건에 맞는 엔티티를 찾을 수 없습니다. 그래프가 올바르게 구축되었는지 확인하십시오."`

## 변경 사항

### 1. `backend/app/clients/mirofish.py`

`get_simulation_state()` 메서드 추가. `GET /api/simulation/{id}`를 호출하여 시뮬레이션 상태를 확인.

### 2. `backend/app/services/simulation_orchestrator.py`

`_step_create_prepare()`에서 prepare 폴링 완료 후 `get_simulation_state()`를 호출하여 상태가 `"ready"`인지 검증. `"ready"`가 아니면 `RuntimeError`를 발생시켜 파이프라인을 조기 중단.
