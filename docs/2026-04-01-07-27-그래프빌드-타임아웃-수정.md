## 변경 요약

- Gateway 기본 `graph_build_timeout` 값을 `600.0`초에서 `900.0`초로 상향했다.
- 실제 런타임 override가 `.env`의 `GRAPH_BUILD_TIMEOUT=600`이었기 때문에, `.env`와 `.env.example`도 `900`으로 맞췄다.
- 재테스트 결과 그래프 빌드는 통과했지만, 리포트 생성이 900초를 초과해 두 번째 병목이 확인되었다.
- 리포트 생성은 시뮬레이션/그래프 작업과 달리 장시간 LLM/도구 실행이 이어질 수 있어, Gateway의 report polling timeout을 비활성화하도록 변경했다.
- `poll_until_done()`가 `timeout <= 0` 또는 `None`일 때 무제한 polling 하도록 바꿨고, 기본 `report_timeout` 및 `.env`/`.env.example`의 `REPORT_TIMEOUT`을 `0`으로 맞췄다.
- 원인 분석 결과, MiroFish 그래프 빌드가 내부적으로 최대 600초 동안 episode 처리 완료를 기다린 뒤 최종 그래프 데이터 조회 후에야 task를 `completed`로 바꾸고 있었다.
- Gateway도 동일하게 600초에서 타임아웃을 걸고 있어서, MiroFish가 실제로는 성공 완료하더라도 Gateway가 먼저 `failed`로 처리하는 경쟁 조건이 발생했다.

## 의도

- 그래프 빌드가 느릴 때도 정상 완료된 작업을 Gateway가 조기 실패 처리하지 않도록 한다.
- 외부 서비스 내부 대기 시간과 Gateway 타임아웃이 동일해서 생기는 false failure를 줄인다.
- 재시작 후 실행 중인 gateway 컨테이너에서 `settings.graph_build_timeout == 900.0`을 확인했다.
- 장시간 리포트 생성도 Gateway가 조기 실패 처리하지 않도록 한다.
