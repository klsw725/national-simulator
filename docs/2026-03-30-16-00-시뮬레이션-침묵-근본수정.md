# 시뮬레이션 침묵 근본 수정 — LLM config에 규칙 기반 최소값 강제

> 날짜: 2026-03-30
> 관련: 2026-03-28-10-00-시뮬레이션-침묵방지-웹검색보강.md

## 프롬프트

시뮬레이션에서 라운드 0에만 포스팅이 되고 그 이후에는 조용한 문제. scn_94bab8678e33 시나리오 진단 → geopolitics_enabled 여부와 관계없이 발생.

## 진단

### 증상
- 12개 에이전트, 전부 round 0에서 CREATE_POST 1회씩
- 라운드 1~29: 액션 0건
- 모든 타임스탬프 동일 (=initial_posts 일괄 실행)
- 지정학 이벤트 0건

### 근본 원인
`simulation_config_generator.py`의 `_generate_agent_configs_batch()`가 LLM에게 에이전트 config 생성을 요청할 때:

1. behavior_guidelines로 "activity_level 0.7-0.9으로 설정해라"를 전달
2. LLM이 낮은 activity_level (0.1~0.3)을 반환해도 코드에서 그대로 사용
3. 규칙 기반 fallback(`_generate_agent_config_by_rule`)은 LLM이 **아예 실패**했을 때만 호출
4. activity_level 0.1인 에이전트 → `random.random() < 0.1` → 90% 확률로 비활성

기존 3차 대책(2026-03-28)은 전부 "LLM에게 부탁"하는 형태여서, LLM이 가이드라인을 무시하면 무력화됨.

## 수정

### 변경 파일
`external/mirofish-backend/app/services/simulation_config_generator.py`

### 변경 내용
`_generate_agent_configs_batch()` 내 AgentActivityConfig 구축 루프에서, 지정학 시나리오인 경우 LLM 반환값에 규칙 기반 최소값을 `max()`로 강제:

- `activity_level`: `max(LLM값, 규칙값)` — 예: LLM이 0.2를 줘도 Superpower는 최소 0.75
- `posts_per_hour`: `max(LLM값, 규칙값)` — 예: LLM이 0.1을 줘도 Superpower는 최소 1.0
- `active_hours`: 규칙 기반이 더 넓은 범위면 규칙 기반 사용 — 예: LLM이 [9,10,11]만 줘도 Superpower는 0~23시 전체

### 영향 범위
- 지정학 시나리오(`_is_geopolitical_scenario() == True`)에서만 적용
- 비지정학 시나리오는 기존 동작 유지 (LLM 값 그대로)
- LLM이 규칙보다 높은 값을 반환하면 LLM 값 사용 (`max` 연산)
