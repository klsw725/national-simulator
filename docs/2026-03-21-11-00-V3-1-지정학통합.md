# V3-1 지정학 엔진 ↔ 시뮬레이션 통합 (M1-M4)

> 날짜: 2026-03-21
> 프롬프트: `진행` (prd-next 추천 V3-1 수락)

## 변경 사항

### 신규 파일
- `frontend/src/components/simulation/GeopoliticsView.tsx` — 지정학 분석 결과 뷰. 요약 바 (이벤트/라운드/행위자 수), 행위자 pills, 라운드별 이벤트 타임라인 (액션 타입 색상 코딩, magnitude 바). 1회성 API fetch.

### 수정 파일
- `backend/app/services/simulation_orchestrator.py`:
  - `_step_geopolitics_analysis(scenario_id, result_id, actions)`: 시뮬레이션 에이전트를 GeopoliticalActorState로 매핑 (상위 10개, 액션 빈도 기준 정렬). 소셜 액션을 GeopoliticsEvent로 변환 (GEOPOLITICS_ACTION_MAP 활용). DecisionEngine.run_simulation(3 rounds) 호출. 결과를 geopolitics_events 테이블에 저장.
  - `_collect_and_store_results`: geopolitics_enabled=true이면 `_step_geopolitics_analysis()` 자동 호출. 실패 시 graceful fallback.
- `backend/app/routers/simulation.py`:
  - CP6 체크포인트: `checkpoint:geopolitics` 추가 (editable=False)
  - 3개 API: `GET /geopolitics` (요약), `GET /geopolitics/events` (이벤트 목록), `GET /geopolitics/timeline` (라운드별)
- `frontend/src/components/simulation/SimulationPanel.tsx` — "지정학" 탭 추가 (completed 상태에서 표시)
- `frontend/src/lib/gatewayApi.ts` — getGeopoliticsSummary(), getGeopoliticsTimeline() 추가

### 핵심 설계
1. **규칙 기반**: DecisionEngine은 LLM 미사용. 수 초 내 완료. 파이프라인 시간 영향 최소.
2. **에이전트 → 행위자 매핑**: 시뮬레이션 액션의 agent_name을 행위자로 사용. 액션 빈도 기준 상위 10개 선택. 초기 상태는 순위 기반 휴리스틱.
3. **geopolitics_enabled=false**: 스킵. 기존 파이프라인 변경 없음.
4. **연쇄 분석**: DecisionEngine.apply_event_with_cascade()로 cascade 이벤트 전파. max_depth=3, decay=0.7.
