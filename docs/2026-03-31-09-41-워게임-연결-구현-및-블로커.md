## 블로커: subprocess IPC vs Docker 컨테이너 분리

### 에러
```
[Errno 2] No such file or directory: '/external/mirofish-backend/uploads/simulations/sim_.../simulation_config.json'
```

### 원인
`_start_wargame_process()` (simulation_orchestrator.py:457)가 **Gateway 컨테이너 안에서** MiroFish의 `run_parallel_simulation.py`를 subprocess로 직접 실행하려 함. 하지만:

1. MiroFish의 `simulation_config.json`은 **MiroFish 컨테이너**의 `/app/uploads/` 에 있음
2. `run_parallel_simulation.py`와 OASIS 패키지도 **MiroFish 컨테이너**에만 설치됨
3. Gateway 컨테이너에서는 파일도, 패키지도 접근 불가

v11 스펙의 IPC Round Control은 Gateway와 MiroFish가 **같은 프로세스 공간**에 있다고 가정했으나, 실제 배포는 Docker 컨테이너로 분리됨.

### 해결 방안

MiroFish API에 라운드 제어 HTTP 엔드포인트를 추가하여, subprocess IPC를 HTTP 기반으로 전환:

```
POST /api/simulation/{id}/start_round_control  — round_control_enabled로 시뮬레이션 시작
POST /api/simulation/{id}/proceed              — proceed 신호 + inject_context
GET  /api/simulation/{id}/round_status         — 현재 라운드 상태/완료 여부
POST /api/simulation/{id}/stop_round_control   — 시뮬레이션 종료
```

Gateway 오케스트레이터가 stdin/stdout IPC 대신 이 HTTP 엔드포인트를 호출하도록 수정.
