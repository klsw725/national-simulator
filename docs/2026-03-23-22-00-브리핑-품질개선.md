# 브리핑 리포트 품질 개선

> 날짜: 2026-03-23
> 관련: briefing_generator.py

## 프롬프트

```
리포트 퀄리티좀 올리자
→ 브리핑 보고서가 모호하고 반복적, 구체적 숫자 없음
→ 원인 분석: 시스템에 정량적 데이터가 있으나 브리핑에 주입되지 않음
```

## 근본 원인

1. `_summarize_simulation_actions()`: 액션 전체를 카운트 5줄 + 잘린 이벤트 5개로 축소
2. `_summarize_geopolitics_events()`: magnitude, target_actor_ids 미조회
3. 긴장도 궤적(tension trajectory) 미사용
4. decision_points 긴장 임계 돌파 기록 미사용
5. LLM 프롬프트가 "근거 중심"이라 했지만 근거 자체를 제공하지 않음

## 변경 사항

### `_summarize_simulation_actions()` 전면 재작성
- 행위자별: 건수 + 유형 분포 (geopolitics_label 사용)
- 행위자 간 상호작용 패턴 (인용/리포스트/반응 관계)
- 라운드별 핵심 행동 + 대표 액션 원문 (300자)

### `_summarize_geopolitics_events()` 전면 재작성
- 라운드별 긴장도 추이 (AVG magnitude)
- 행위자 → 대상 관계 매핑 (target_actor_ids 파싱)
- 최고 긴장도 이벤트 상위 5건 (magnitude + 원문)

### `_build_tension_trajectory()` 신규
- `geopolitics_events` GROUP BY round_number → AVG/MAX magnitude
- `decision_points` 긴장 임계 돌파 기록
- 텍스트 기반 바 차트 (█ 블록)

### `BRIEFING_PROMPT` 전면 재작성
- 각 섹션에 "구체적 숫자/행위자명 인용" 의무화
- "데이터가 없는 섹션은 '데이터 없음'으로 명시" 강제
- "같은 인용문 반복 금지" 규칙
- 섹션 구조 변경:
  - §4 "시뮬레이션 라운드별 진행" → 시간순 내러티브
  - §부록 → 데이터 소스 + 신뢰도 + 한계점

### `generate()` 쿼리 확장
- `geopolitics_events`에서 `magnitude`, `target_actor_ids` 추가 조회
- 라운드 순서대로 정렬 (DESC → ASC)
- LIMIT 500 → 1000 (더 많은 이벤트 포함)
