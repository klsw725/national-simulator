# 시뮬레이션 그래프 생성 fail-fast 전환

## 사용자 프롬프트

> 시뮬레이션 진행시 꼭 그래프 생성이 되었으면 하는데 생성이 안되도 넘어가진다?

## 문제

`simulation-service`의 LangGraph 노드들이 LLM/DB 실패를 silent하게 삼키고 빈 결과로 다음 단계로 진행했다. 사용자 관점에서는:

- 엔티티 추출 LLM 실패 → 빈 그래프로 시뮬레이션이 끝까지 진행 → "완료" 표시
- 리포트 LLM 실패 → `[보고서 생성 실패] N라운드 완료` 플레이스홀더 문자열로 대체 → 역시 "완료" 표시
- 액터 프로파일 LLM 실패 → `regional/unknown/defensive` 기본값 fallback

즉 장애가 완료로 위장되었다.

## 적용 (전면 fail-fast)

각 그래프 노드를 "3회 지수 백오프 재시도 → 최종 실패 시 `phase=failed` emit + `RuntimeError` raise"로 전환. 최상위 `command_listener`의 모든 실행 경로(`_start_simulation`, `_apply_decision`, `_resume_simulation`, `_start_whatif`)가 이를 catch하여 `emitter.emit_error` + `simulation_status='failed'` + `status='failed'`로 UI에 전파.

### 변경 파일

| 파일 | 변경 |
|---|---|
| `simulation-service/app/graph/nodes/relations.py` | silent fallback 제거. 3회 재시도 후 `RuntimeError`. |
| `simulation-service/app/graph/nodes/report.py` | LLM 리포트 생성 실패 시 플레이스홀더 대신 `RuntimeError`. |
| `simulation-service/app/graph/nodes/actors.py` | 액터 프로파일 기본값 fallback 제거. 액터별 3회 재시도 후 실패 시 `RuntimeError`. `get_emitter` import를 모듈 최상위로 이동. |
| `simulation-service/app/services/command_listener.py` | `_apply_decision`/`_resume_simulation`을 `_start_simulation::_run`과 동일한 try/except 래퍼로 감쌈 (`emit_error` + `_update_scenario_status("failed")`). |
| `tests/e2e_simulation_v2.py` | `--expect-failure` CLI 플래그 추가. fail-fast 시나리오에서 `error` 수신 & `report_ready` 미발행을 검증. |
| `AGENTS.md` | "규칙 지뢰"에 그래프 노드 fail-fast 원칙 추가. |

### 재시도 파라미터

| 모듈 | 상수 | 기본값 |
|---|---|---|
| relations.py | `_EXTRACT_RETRY`, `_EXTRACT_DELAY` | 3, 2.0s |
| report.py | `_REPORT_RETRY`, `_REPORT_DELAY` | 3, 2.0s |
| actors.py | `_PROFILE_RETRY`, `_PROFILE_DELAY` | 3, 2.0s |

## 실패 전파 체인

```
[graph node] LLM 3회 재시도 실패
    → emit_phase_change(phase="failed")
    → raise RuntimeError(...)
        ↓
[command_listener::_run / _apply_decision / _resume_simulation / _start_whatif]
    except Exception:
        emitter.emit_error(scenario_id, str(exc))
        _update_scenario_status(scenario_id, "failed")
        ↓
[UI] error 이벤트 + scenarios.simulation_status='failed' 수신
```

## 검증

### 정상 경로 (happy path)
```bash
uv run python tests/e2e_simulation_v2.py
```
기대: `report_ready` 수신, `simulation_status='completed'`.

### fail-fast 경로
```bash
export OPENAI_API_KEY=sk-invalid   # 또는 OPENAI_BASE_URL=http://invalid:9999
docker compose restart simulation-service
uv run python tests/e2e_simulation_v2.py --expect-failure
```
기대: `error` 이벤트 수신, `report_ready` 미발행, `simulation_status='failed'`.

## 의도적으로 하지 않은 것

- **ruff / pytest 등 Python 린트·테스트 인프라 신규 도입 안 함.** AGENTS.md 툴링 지뢰 규칙 준수 ("Python 린터·포매터·테스트 러너 없음. 존재하지 않는 인프라를 찾거나 실행하려 하지 말 것").
- **단위 테스트 파일 신규 생성 안 함.** 위와 동일 이유. 기존 `tests/e2e_simulation_v2.py` 러너를 확장하는 방식으로만 fail-fast 검증을 추가.
- **actors.py의 `simulation-service/app/prompts/actor_system.py::ACTOR_PROFILE_PROMPT` 관련 프롬프트 튜닝 안 함.** 재시도 3회로도 실패한다면 프롬프트/LLM 설정 자체의 문제이므로 surgical fail-fast 원칙 외의 변경은 요청 범위를 벗어남.
