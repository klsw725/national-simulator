## 1단계: 전체 코드 품질 점검

Backend 13,123줄(Python) + Frontend 14,468줄(TypeScript)을 대상으로 3개 탐색 에이전트를 병렬 실행하여 분석함.

### 주요 발견 (심각도순)

| 카테고리 | 심각도 | 핵심 파일 |
|----------|--------|-----------|
| God Router (simulation.py 2,226줄) | CRITICAL | backend/app/routers/simulation.py |
| 무차별 except Exception (38+건) | CRITICAL | backend 전역 |
| 거대 컴포넌트 10개 (400줄+) | HIGH | frontend/src/components/ |
| Frontend 무음 에러 처리 (.catch(() => {})) | HIGH | 3개 파일 |
| 모놀리식 API 레이어 (gatewayApi.ts 682줄) | HIGH | frontend/src/lib/ |
| 코드 중복 패턴 (900+건) | MEDIUM | 전체 |

## 2단계: 실행한 리팩토링

### Phase 1: simulation.py 라우터 분할 (CRITICAL)

**변경 전**: `backend/app/routers/simulation.py` — 2,226줄, 50개 엔드포인트, 6개 도메인 혼재

**변경 후**: 6개 라우터 + 1 공유 헬퍼

| 새 파일 | 역할 | 줄 수 |
|---------|------|-------|
| `_helpers.py` | 공유 유틸리티 (get_sim_row, row_to_seed_response, row_to_decision_point) | 45 |
| `seed.py` | 시드 생성/조회/옵션/파라미터추천 (4 endpoints) | 274 |
| `simulation_run.py` | 시뮬레이션 시작/재시도/계속/체크포인트/상태/결과 (8 endpoints) | 771 |
| `simulation_live.py` | 실시간 모니터링/스냅샷/감사/관측/지정학데이터 (13 endpoints) | ~310 |
| `decision_point.py` | 의사결정 포인트 CRUD + resolve (4 endpoints) | ~180 |
| `briefing.py` | 브리핑 CRUD + 내보내기 (7 endpoints) | ~200 |
| `simulation_interactive.py` | 인터랙티브/일시정지/재개/What-If/인터뷰 (14 endpoints) | 501 |

`main.py` 업데이트: 기존 `simulation` 단일 임포트를 6개 라우터 임포트로 교체.

**검증**: FastAPI 앱 로드 성공, 102 라우트 등록, 50개 엔드포인트 100% 보존.

### Phase 2: SimulationOrchestrator 분할 (판단 변경)

분석 결과 분할 **불필요**로 판단:
- 18개 메서드가 단일 MiroFish 파이프라인을 위해 존재하는 응집도 높은 클래스
- 분할 시 오케스트레이터 간 조율 복잡도 증가
- 각 step 메서드는 20-80줄로 적절한 크기

### Phase 3: MaplibreViewer 컴포넌트 분해

**변경 전**: `MaplibreViewer.tsx` — 1,595줄

**변경 후**:
- `MaplibreViewer.tsx` — 911줄 (지도 컨테이너 + Source/Layer 정의)
- `MapPopupContent.tsx` — 686줄 (13가지 엔티티 타입 팝업 렌더링)

**검증**: `tsc --noEmit` 통과 (에러 0).

### Phase 4: Frontend 무음 에러 처리 수정

| 파일 | 변경 내용 |
|------|-----------|
| `useSimulation.ts:224` | `.catch(() => {})` → `.catch((e) => { console.warn(...) })` |
| `CheckpointReview.tsx:47` | `.catch(() => {})` → `.catch((e) => { console.warn(...) })` |
| `DecisionPointView.tsx:51` | `.catch(() => {})` → `.catch((e) => { setResolveError(...) })` + 에러 UI 추가 |

DecisionPointView는 사용자 액션(의사결정 확정)의 실패이므로 `resolveError` 상태 + 에러 메시지 UI를 추가함.
