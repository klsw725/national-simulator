# Checkpoint UI (Human-in-the-Loop)

**Date**: 2026-03-20 23:45
**Prompt**: Implement the frontend checkpoint UI for the pipeline Human-in-the-Loop feature

## Changes

### Types (`simulation.ts`)
- Added `PipelineMode` type (`'auto' | 'checkpoint'`)
- Added `CheckpointData` interface for checkpoint API response
- Added `mode: PipelineMode` to `ScenarioFormData`

### Gateway API (`gatewayApi.ts`)
- Updated `startSimulation()` to accept `mode` parameter
- Added `getCheckpoint()` for fetching checkpoint data
- Added `continueSimulation()` for resuming pipeline with optional edits

### Hook (`useSimulation.ts`)
- Added `checkpointData` and `pipelineMode` state
- Modified `pollStatus` to detect `checkpoint:*` statuses, stop polling, and fetch checkpoint data
- Added `continueCheckpoint(edits?)` method that resumes pipeline and restarts polling
- Modified `createAndRun` to pass pipeline mode to `startSimulation`

### CheckpointReview Component (NEW)
- Step indicator showing progress through 5 checkpoints (seed, ontology, graph, profiles, config)
- Editable textarea for seed text (CP1)
- Readonly ontology viewer showing entity_types and edge_types (CP2)
- Simple completion messages for graph (CP3) and profiles (CP4)
- Editable number input for max_rounds (CP5)
- Continue/Cancel action buttons

### PipelineProgress
- Added `checkpoint:*` status mapping to `activeStepIndex()`
- Added `"paused"` step status with amber/yellow styling
- Added `onReview` prop with a review button on paused steps

### ScenarioForm
- Added pipeline mode segment toggle ("auto" / "checkpoint")
- Passes mode in form submission data

### SimulationPanel
- Integrated CheckpointReview: shown in "progress" tab when checkpoint is active
- Wired `onContinue` and `onCancel` handlers
