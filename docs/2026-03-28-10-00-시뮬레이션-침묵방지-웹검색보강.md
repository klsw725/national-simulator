# 시뮬레이션 침묵 방지 + 웹 검색 보강

**날짜**: 2026-03-28
**프롬프트**: "의미적인 보고서를 생성하려면 어떻게 해야 할까? / 데이터 없는게 최대한 웹 검색을 통해서 보강해서 의견을 만들었으면 좋겠는데 / 순차적으로 진행하자"

## 문제

시뮬레이션에서 모든 행위자가 DO_NOTHING(전략적 관망)을 선택하면 보고서가 "데이터가 없어서 못했다"로 귀결됨. 원재료(행위자 행동)가 0이면 어떤 후처리도 무의미.

## 변경 사항

### 1순위: SIMULATION_REQUIREMENT 수정 (근본 원인 해소)

**파일**: `backend/app/services/simulation_orchestrator.py`

`SIMULATION_REQUIREMENT` 상수에 【필수 행동 규칙】 섹션 추가:
- 각 행위자 최소 1회 CREATE_POST 또는 QUOTE_POST 필수
- DO_NOTHING은 다른 행동 수행 후에만 선택 가능
- 강대국/지역강국은 적극적 행동 비율 50% 이상

### 2순위: sparse 시뮬레이션 감지 + 로깅

**파일**: `backend/app/services/simulation_orchestrator.py`

- `_compute_do_nothing_ratio()` 정적 메서드 추가
- `_collect_and_store_results()`에서 DO_NOTHING 비율 > 70% 시 경고 로깅

### 3순위: BriefingGenerator 웹 검색 보강 (보험용 fallback)

**파일**: `backend/app/services/briefing_generator.py`

- `_is_sparse_scenario()`: DO_NOTHING > 70%인지 판단
- `_enrich_with_web_search()`: DuckDuckGo 뉴스 검색으로 외부 컨텍스트 수집
- `_extract_actor_names()`: 시뮬레이션 결과에서 행위자명 추출
- `SPARSE_BRIEFING_PROMPT`: 침묵 시나리오 전용 프롬프트 (OSINT + 웹 검색 + 반사실적 분석)
- `generate()` 분기: sparse 감지 시 SPARSE_BRIEFING_PROMPT + 웹 검색 사용
- 기존 `BRIEFING_PROMPT`와 정상 시나리오 로직은 변경 없음

## 흐름

```
시뮬레이션 완료
    ↓
_collect_and_store_results: DO_NOTHING 비율 계산 → >70%이면 경고 로그
    ↓
BriefingGenerator.generate() 호출
    ↓
_is_sparse_scenario() → True?
    ├── No → 기존 BRIEFING_PROMPT (변경 없음)
    └── Yes → 웹 검색 수행 → SPARSE_BRIEFING_PROMPT 사용
              ├── DuckDuckGo 뉴스 검색 (지역 + 시나리오 키워드)
              ├── OSINT 데이터 (ShadowBroker, 기존)
              ├── 침묵 자체의 전략적 의미 분석
              └── 반사실적 시나리오 (What-If) 생성
```

## 검증

- LSP 진단: 에러 없음 (openai import 경고는 기존 환경 이슈)
- 기존 로직 미파괴: BRIEFING_PROMPT 미변경, 정상 시나리오 경로 동일
- 새 의존성 없음: WebSearchService, duckduckgo-search 모두 기존 의존성
