## 변경 사항

- `simulation-service/app/services/command_listener.py`
  - 인터럽트로 생성된 워게임 decision payload를 `decision_points` 테이블에 canonical 형태로 저장하도록 수정
  - `user_decision` 처리 시 대응되는 pending decision row를 resolved로 마킹하도록 수정
  - `resume_simulation` 경로도 interrupt/completed/running 상태를 다시 반영하도록 수정

- `backend/app/routers/decision_point.py`
  - 기존에 저장되지 않았던 `intervention_required` 이벤트를 기준으로 pending decision row를 materialize하는 fallback 추가
  - `list/get/resolve` decision point API가 paused 시나리오의 이벤트 기반 decision을 복구해서 노출 가능하도록 수정

- `backend/app/routers/wargame_v2.py`
  - `/checkpoint` 응답이 checkpoint 내부 값이 비어 있어도 최신 pending intervention event를 사용해 `decision_point`와 `has_pending_decision`을 복구하도록 수정

- `frontend/src/components/wargame/WarRoom.tsx`
  - V2 워룸이 SSE에서 새 `intervention_required` 이벤트를 못 받은 경우에도 `useWargame()`의 `/wargame_status` hydration 결과를 fallback으로 사용하도록 수정
  - paused 상태에서 새로고침/재진입 후에도 decision modal이 다시 렌더링되도록 수정

- `frontend/src/lib/api/wargameApi.ts`
  - V2 decision submit 시 `selected_option_id`도 함께 전송하도록 수정

- `frontend/src/types/simulation.ts`
  - 워게임 decision payload가 legacy/v2 두 형태를 모두 표현할 수 있도록 타입 확장

## 검증

- `uv run python -m py_compile app/routers/decision_point.py app/routers/wargame_v2.py`
- `uv run python -m py_compile app/services/command_listener.py`
- `frontend`: `npm run build` 성공
- `docker compose up -d --build gateway simulation-service frontend` 후 live 재검증
  - `GET /api/scenario/scn_4cfdfde91db2/checkpoint` → `has_pending_decision: true`
  - `GET /api/scenario/scn_4cfdfde91db2/decision_points?status=pending` → pending decision 1건 노출
