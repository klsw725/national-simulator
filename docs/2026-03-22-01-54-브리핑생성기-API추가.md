# 작업 요약

- `backend/app/services/briefing_generator.py` 파일을 신규 생성했다.
  - `BriefingGenerator` 클래스와 `generate(scenario_id)` 메서드를 구현했다.
  - 시나리오/시드/시뮬레이션 결과/지정학 이벤트/리포트를 DB에서 수집한다.
  - 수집 데이터를 요약해 브리핑 프롬프트를 구성하고 LLM을 호출한다.
  - `temperature=0.3`, `max_tokens=4096`으로 일관된 브리핑 생성을 적용했다.
  - 생성 결과를 `briefings` 테이블에 저장하고 `{id, scenario_id, content, version, created_at}`를 반환한다.

- `backend/app/database.py`의 `SCHEMA`에 `briefings` 테이블과 인덱스를 추가했다.
  - `briefings(id, scenario_id, content, version, created_at, updated_at)`
  - `idx_briefings_scenario` 인덱스

- `backend/app/routers/simulation.py`에 브리핑 API 3개를 추가했다.
  - `POST /api/scenario/{scenario_id}/briefing/generate`
    - 시나리오 존재 및 `simulation_status == completed` 확인
    - lazy import로 `BriefingGenerator` 호출
  - `GET /api/scenario/{scenario_id}/briefing`
    - 최신 브리핑 조회, 없으면 404
  - `PUT /api/scenario/{scenario_id}/briefing`
    - 요청 바디 `{"content": "..."}` 검증
    - 최신 브리핑 내용 수정, 버전 증가, `updated_at` 갱신

- 검증
  - `uv run python -m compileall backend/app/services/briefing_generator.py backend/app/database.py backend/app/routers/simulation.py` 실행 완료
  - 변경 파일 기준 문법 오류 없음
