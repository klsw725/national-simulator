# 시뮬레이션 파이프라인 데드락 수정

## 프롬프트

> 시뮬레이션이 잘 돌아가는지 파악해봐 → 수정

## 문제

시뮬레이션 시작 시 `POST /api/scenario/{id}/simulate` → 202 반환 후 파이프라인이 `OSINT snapshot saved`까지만 진행되고 멈춤.

- `simulation_results` 테이블에 row 미생성
- `/api/scenario/{id}/status` → 404
- 시나리오 status가 `created`에서 `simulating`으로 갱신 안 됨

## 원인

`start_simulation` 엔드포인트가 `Depends(get_db_tx)`를 사용.
Starlette의 의존성 생명주기에서 `get_db_tx`의 트랜잭션 커밋은 백그라운드 태스크 완료 **후**에 실행됨.

```
1. get_db_tx 트랜잭션 시작 → INSERT simulation_results (미커밋)
2. background_tasks.add_task(run_pipeline) 등록
3. 응답 202 전송
4. 백그라운드 run_pipeline 실행 → _step_ontology → _update_status
   → UPDATE simulation_results WHERE id = $2  ← 미커밋 row에 락 대기
5. get_db_tx 트랜잭션 커밋은 백그라운드 태스크 완료 후에 실행
6. 데드락: 4→5 대기, 5→4 대기
```

`ActionLogger.log`는 `pool.acquire()`로 별도 커넥션을 사용하므로 `action_log`에는 기록이 남았지만, `simulation_results` INSERT는 커밋되지 않아 롤백됨.

## 수정

- `backend/app/routers/simulation_run.py`
  - `start_simulation`: `Depends(get_db_tx)` 제거, `pool.acquire()` + 수동 `conn.transaction()` 사용. 트랜잭션 커밋 후 `background_tasks.add_task()` 호출.
  - `continue_pipeline`: 동일 패턴 적용. 워게임 continue, 체크포인트 continue 경로 모두 수정.
  - `get_db_tx` 미사용 import 제거.

## 검증

1. Gateway 리빌드 후 시나리오 생성 + 시드 생성 + `POST /simulate`
2. `simulation_results` row DB 즉시 확인 → 존재 ✅
3. `/api/scenario/{id}/status` → 200 OK ✅ (이전: 404)
4. 파이프라인 `simulating:ontology` → `simulating:graph_build` 정상 전환 ✅
