# 레거시 지정학 개입모드 2단계 정리

## 프롬프트

> 고고고고

## 목적

1단계 제거 이후 남아 있던 레거시 interactive 관련 타입/모델/DB 찌꺼기를 정리한다.

## 변경 사항

### 프론트엔드

- `frontend/src/types/simulation.ts`
  - 삭제:
    - `InjectEventRequest`
    - `InteractiveStatus`

### 백엔드

- `backend/app/models/interactive.py`
  - 삭제:
    - `InteractiveSimulationConfig`
    - `InjectEventRequest`
    - `InteractiveStatus`
  - 유지:
    - `WhatIfCreateRequest`
    - `WhatIfBranch`
    - `WhatIfComparison`

- 삭제:
  - `backend/app/services/tension_analyzer.py`
    - orphan 상태였고, `tension_alert` decision point 생성만 담당했으나 호출 경로 없음

- `backend/app/database.py`
  - `injected_events` 테이블 및 인덱스 생성 구문 제거

### 개발 DB 정리

- PostgreSQL에서 레거시 `injected_events` 테이블 직접 삭제

```sql
DROP TABLE IF EXISTS injected_events;
```

## 남겨둔 것

- `backend/alembic/versions/001_initial_schema.py`의 `injected_events` 정의는 **히스토리 migration**이므로 수정하지 않음
- `backend/app/geopolitics/router.py`의 `inject_event`는 레거시 interactive와 무관한 일반 지정학 이벤트 주입 API이므로 유지

## 검증

- `python3 -m py_compile ...` 통과
- `docker compose build gateway frontend` 통과
- 검색 결과 기준 레거시 interactive 잔존 참조는 다음만 남음:
  - alembic historical migration의 `injected_events`
  - 일반 geopolitics router의 `inject_event`
