## 변경 사항

### 수정 파일

- `backend/app/services/simulation_orchestrator.py`
  - `determine_recovery_point(row)`: 기존 MiroFish ID(project_id, graph_id, simulation_id)로 복구 지점 추론
  - `run_from_failure()`: 복구 지점부터 파이프라인 재실행 (ontology → graph → create → run → report)
  - 실패 시 에러 로깅 + pipeline.retry_failed 감사 로그

- `backend/app/routers/simulation.py`
  - `POST /{scenario_id}/retry` 엔드포인트 추가
  - failed 상태 검증 + MiroFish 헬스체크
  - determine_recovery_point → run_from_failure 백그라운드 실행

- `frontend/src/lib/gatewayApi.ts`
  - `retrySimulation(scenarioId)` 함수 추가

- `frontend/src/components/simulation/SimulationPanel.tsx`
  - 에러 배너에 "마지막 체크포인트에서 재시도" 버튼 추가 (failed 상태일 때만)
  - RotateCcw 아이콘 import 추가

### 설계 결정

- 스키마 변경 없음: 기존 simulation_results의 mirofish_project_id, graph_id, mirofish_simulation_id로 복구 지점 추론
- run_from_failure는 run_pipeline과 동일한 step 메서드를 재사용 (코드 중복 없음)
- 복구 지점은 ontology → graph_build → create_prepare → run_simulation 4단계
