## 변경 사항

### M1: PG 스키마 (database.py)

- `ontology_versions` 테이블: version, schema_hash, schema_json, change_summary, is_breaking, created_by
- `simulation_results`에 `ontology_version TEXT` 컬럼 추가 (ALTER TABLE)
- UNIQUE 인덱스: `idx_ontology_versions_version(version)`
- 일반 인덱스: `idx_ontology_versions_hash(schema_hash)`

### M2: 버전 등록 + diff (ontology/versioning.py 신규)

- `OntologyVersioning.register()` — 새 버전 등록. 스키마 해시 비교로 동일 스키마 중복 등록 방지
- `OntologyVersioning.diff()` — 두 등록된 버전 간 변경 목록 계산
- `OntologyVersioning.compute_diff()` — 순수 함수. entity_types/edge_types 비교 → sdo_type_added/removed, field_added/removed, description_changed
- `_schema_hash()` — SHA256 기반 정규화 해시 (JSON sort_keys)

### M3: 하위 호환성 검증 (ontology/versioning.py)

- `OntologyVersioning.validate()` — 새 스키마를 최신 버전과 비교하여 호환성 판단
- Breaking 변경: field_removed, field_type_changed, required_added, sdo_type_removed
- Non-breaking 변경: field_added_optional, sdo_type_added, description_changed
- `register()` 호출 시 자동으로 `is_breaking` 플래그 설정

### API 라우터 (ontology/router.py 신규)

- `GET /api/ontology/versions` — 버전 목록
- `POST /api/ontology/versions` — 새 버전 등록
- `GET /api/ontology/versions/latest` — 최신 버전
- `GET /api/ontology/versions/diff?from=X&to=Y` — 버전 간 차이
- `GET /api/ontology/versions/{version}` — 특정 버전 조회
- `POST /api/ontology/versions/validate` — 호환성 검증

### main.py

- `ontology_router` 등록

## M4 보류 사유

M4(MiroFish 연동)는 시뮬레이션 실행 시 MiroFish가 생성한 온톨로지를 자동으로 버전 등록하는 기능이다. SimulationOrchestrator의 파이프라인 내에서 MiroFish API 응답을 파싱하여 `OntologyVersioning.register()`를 호출해야 하며, 이는 MiroFish 응답 형식에 대한 추가 탐색이 필요하다.
