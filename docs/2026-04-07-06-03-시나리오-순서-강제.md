# 시나리오 순서 강제

- 시간: 2026-04-07 06:03 UTC
- 사용자 프롬프트: `시나리오 순서는 다 보장 되어야 해` / `일단 구현해`

## 변경 사항

### 백엔드
- `backend/app/routers/simulation_v2.py`
  - 시뮬레이션 시작 전에 시나리오 존재 여부, `seed_status == completed`, seed row 존재 여부를 검증하도록 수정.
  - seed가 없으면 `400 Seed must be generated before starting simulation`을 반환하도록 수정.
  - 지역/질문 기반 synthetic seed fallback 제거.
  - `/simulate`, `/start_v2`가 더 이상 `seed_status`를 임의로 `completed`로 바꾸지 않도록 수정.

### 프론트엔드
- `frontend/src/hooks/useSimulation.ts`
  - `createAndRun()`이 시나리오 생성 후 즉시 `/simulate` 하지 않고, 먼저 `generateSeed()`를 호출한 다음 시뮬레이션을 시작하도록 수정.
  - seed 생성 단계의 상태를 `generating -> completed`로 UI에 반영.
- `frontend/src/lib/api/seedApi.ts`
  - `generateSeed()` 반환 타입을 실제 응답(`SeedResponse`)과 맞춤.

## 검증

- `frontend`: `npm run build` 통과
- `backend`: `uv run python -m py_compile app/routers/simulation_v2.py app/routers/seed.py` 통과

## 런타임 메모

- 컨테이너 재시작만으로는 코드가 반영되지 않아 `gateway/frontend` 이미지를 재빌드함.
- 재빌드 후 기존 조사 대상 시나리오(`scn_d06c81bebd7c`)는 런타임 DB에서 더 이상 조회되지 않아, 같은 ID 기준의 HTTP 재검증은 연속적으로 수행하지 못함.
- 따라서 본 변경의 최종 런타임 검증은 새 시나리오 생성 → seed 생성 → simulate 허용, seed 없이 simulate 400 반환 순서로 다시 확인하는 것이 적절함.
