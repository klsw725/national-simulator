# 워게임 HTTP 라운드 제어 구현

## 프롬프트

> 빠진거 없이 다 구현하고 알려줘 → 진행해 (HTTP 라운드 제어)

## 문제

v11 워게임 파이프라인의 `_start_wargame_process()`가 Gateway 컨테이너에서 MiroFish의 `run_parallel_simulation.py`를 subprocess로 직접 실행하려 했으나, Docker 컨테이너 분리로 파일/패키지 접근 불가.

```
[Errno 2] No such file or directory: '/external/mirofish-backend/uploads/simulations/sim_.../simulation_config.json'
```

## 해결: HTTP 라운드 제어

subprocess stdin/stdout IPC를 MiroFish HTTP 엔드포인트로 전환.

### MiroFish 변경

1. `app/services/simulation_runner.py` — round-controlled subprocess 관리 추가
   - `_rc_processes`, `_rc_locks` 클래스 변수
   - `start_round_controlled()` — round_control_enabled로 subprocess 시작, stdin/stdout PIPE, ready 신호 대기
   - `proceed_round()` — proceed 신호 전송 → round_complete 대기 → 반환
   - `stop_round_controlled()` — stop 신호 전송 → 프로세스 정리
   - `_read_control_stdout_line()` — 타임아웃 있는 stdout 라인 읽기

2. `app/api/simulation.py` — HTTP 엔드포인트 3개
   - `POST /api/simulation/round_control/start`
   - `POST /api/simulation/round_control/proceed`
   - `POST /api/simulation/round_control/stop`

### Gateway 변경

1. `backend/app/clients/mirofish.py` — HTTP 메서드 추가
   - `start_round_control()` (timeout=120s)
   - `proceed_round()` (timeout=300s)
   - `stop_round_control()`

2. `backend/app/services/simulation_orchestrator.py` — subprocess IPC → HTTP 전환
   - `_start_wargame_process()` → `mf.start_round_control()` 호출
   - `_send_control_signal()` → `mf.proceed_round()` / `mf.stop_round_control()` 호출
   - `_wargame_paths()`, `_wargame_processes` 제거

### 이전 세션에서 수행한 연결 작업

- `GET /api/scenario/{id}/wargame_status` 폴링 폴백 엔드포인트 (simulation_run.py)
- `ScenarioForm.tsx` — `wargame_enabled: true` 기본값
- SSE 엔드포인트 `/api/scenario/{id}/events` 등록 확인

## E2E 테스트 결과

### 성공
- 워게임 파이프라인 Phase 0 (ontology → graph → profiles) ✅
- HTTP round_control/start → MiroFish subprocess 시작 → ready 신호 수신 ✅
- 5라운드 round_control/proceed → round_complete 왕복 정상 ✅
- wargame_state DB 기록 정상 (round 5/5, status: running) ✅
- wargame_status API 정상 반환 ✅

### 후속 수정
- 지정학 엔진 초기화를 첫 라운드 액션만이 아니라 **누적 round_actions 기반**으로 변경
- 소셜 액션 매핑을 엔진이 이해하는 이벤트 타입으로 정렬
  - `quote_post/repost/like_post -> diplomatic_statement`
  - `follow -> treaty_sign`
- `_apply_simulation_actions_to_engine()`가 적용한 이벤트를 `round_result.events`에 포함하도록 변경
- `diplomatic_statement` 기반 시뮬레이션 이벤트는 magnitude 0.55로 저장되어 `should_pause()` 판정 대상이 되도록 조정

### 최종 검증
- 워게임 파이프라인이 실제로 `wargame:paused:round_1` 상태까지 진입 ✅
- `geopolitics_events` 4건 생성 확인 ✅
- `decision_points`에 `geopolitics_direction` pending 1건 생성 ✅
- `wargame_status`가 `phase: "decision"` + 실제 옵션 4개 반환 ✅
- 실제 프론트엔드에서 선택 카드가 표시되고, Mock이 아닌 실제 decision point ID(`dp_...`) 기반으로 해소 가능 상태 확인 ✅
